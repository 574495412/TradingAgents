# 双向基差：长期取证与统计准备

日期：2026-10-16。经济假说和执行规则保持原版本；本轮改动集中在存储、核验及预定统计实现。
尚无通过稳定性门槛的盈利因子，三十日加独立后三十日主检验尚未登记或启动。

## 真实日志容量

对已封存的v034真实输入逐字节压缩、解压并核对完整SHA256：

| 日志 | 原字节 | 压缩字节 | 压缩耗时 |
| --- | ---: | ---: | ---: |
| 公开原文 | 36,480,952 | 7,985,560 | 约0.965秒 |
| 财务帧 | 9,261,727 | 714,418 | 约0.068秒 |

根据该短窗口的经常性输入，未压缩记录速率估算为每分钟4,880,872字节，六十天约421.7 GB。
测量时本机可用约305 GiB，不能直接以平面日志开始长期记录。
估算不含未来预热、资金费请求、重试和额外审计副本；短窗口压缩率也不是长期容量保证。
原结果及计算来源保存在 `paper_capacity_v036/`，未借此重新计算任何策略收益。

新存储版本 `segmented-gzip-v1` 每段以4 MiB解压内容或1024条事件为目标，单条原文不截断。
段关闭并同步、原子改名、同步目录后，才追加并同步独立索引链；决策提交前封闭原文段。
压缩保持原来的事件序号、接收时间、事件哈希与完整解压行，另核验压缩文件和解压内容的身份。
恢复时已提交段逐条重算；未入索引的完整段与半段隔离保留，不能用来补写已提交账本。

v038将v034的3095条原文和5个财务帧完整转写：所有原文、事件链终点和解压字节相同，两个成本账户重建相同。
它是存储格式重放，不能算新策略或新增收益样本。

## 逐前缀独立核验

`--streaming`按每个账户帧声明的前缀推进，只缓存每合约300根分钟、近期指数请求与少量时钟记录。
原文包装的完整成员身份写入临时SQLite索引，成员索引只能从已验证的原事件链生成，退出时清理。
首次原文冲突须具有两份先前原文及收盘61秒之后的精确确认；未成熟推送保留等待，进程会话重启撤销旧等待。
每帧增量超过10000条或256 MiB时停止审计并保留原文，避免异常长断层造成无界内存使用。
财务审计也可顺序消费帧，只保留实际成交仍需引用的信号帧；逐帧现金、含浮亏权益、费用与库存仍独立计算。

v045与v043在同一v042真实窗口上核验3575条原文和8个账户帧，原文计数、方向公式、两账户财务及精确恢复等八项主要结果一致。
流式审计最多缓存66000根分钟，最大单帧原文增量894条。v046保留两个审计结果的身份及逐字段一致性。
每次审计同时归档主审计器、独立财务器、冲突核验器、恢复边界及流式游标源码，记录实际运行库身份。
审计仍执行完整账户恢复；长账本的恢复耗时没有因为原文流式化就自动解决。

新增隔离重放在未发布的独立对象内应用全部财务帧，最后逐字段核对检查点；任一失败都不能返回运行账户。
它保留同一十进制上下文、活动规则、事件序号和输入哈希，只省去恢复中逐帧复制整段历史的事务副本。
原实时提交仍保留逐帧原子事务，不能把离线恢复的优化直接用于活账户提交。
四组人工非零库存／资金费检查与三种失败反证通过，真实v042的完整审计与v048隔离流式审计财务结果相同。

单合约人工空仓曲线500帧的原恢复约0.497秒、隔离恢复约0.023秒，2000帧分别约7.140秒与0.087秒。
43200帧的隔离完整重放约1.872秒，另行独立财务重建约1.409秒；该规模未运行原事务恢复作比较。
v047保存人工源码、检查点与结果。它没有真实市场输入、非零库存或220合约规模，不能将这些耗时称为真实月级恢复性能。

随后v049用固定220个合约名称、人工中性报价和空仓连续运行43200帧，隔离完整重放约186.207秒，独立财务重建约126.236秒，终态逐字段相等。
这次没有实际行情日志读取、非零库存、真实费用或原事务方式的同规模对照；不能据此声称真实进程恢复只需186秒。
标准实时恢复路径仍使用原事务重放，隔离优化目前用于独立离线审计；两个成本账户的完整进程恢复还需另测。

库存、挂起入场或资金费复查未完成时，不给出最终收益、胜率或区间。
每阶段至少30个不同的完整初始活动，不能复用活动、拼接赢家或跳过中间时期。
两阶段使用连续但不同的账本，算法与统计版本相同，各自通过必要条件。

每日序列、费用尾部和重采样细节已写入 `profit_factor_bidirectional_plan.md`。

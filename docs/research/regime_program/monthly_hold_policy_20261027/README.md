# 月度持有与8%单仓止损：一次固定反证

2026-10-27。结论：**单仓止损确实改变了持有路径，但关闭它仍未使这套月度趋势盈利，不能取得收益模块准入。** 不继续扫描止损宽度、风险预算或持有窗口，也不据此否定所有趋势或条件性趋势策略。

## 唯一变化与对照

[原始论文](https://fairmodel.econ.yale.edu/ec439/mosk.pdf)的月度持有与本地8%单仓价格止损是不同规则。上一轮139/149个完整周期因止损结束，止损周期中位持有6.83日，因此本轮只预登记一个开／关反证。信号、月度历史流动性候选域、16%名义风险再乘0.8敞口预算、费用、五分钟执行、资金费、生命周期退出与15%持续账户停机均沿用原方案。

关闭单仓价格止损改变了风险合同，不是同风险改善，也不是取消账户停机或实盘授权。新增Freqtrade版本`monthly_hold_v1.py`只增加显式布尔开关与独立恢复身份，不修改原封存引擎；没有用极大的止损参数隐式关停。默认开启时，两条趋势成本对照的完整净值、事件、请求、交易、库存和风险状态与旧结果精确相同，只有显式引擎版本身份不同。

本轮4条新政策账户、2条旧路径桥接复算、1条选定TON退出病例，共7次账户／病例计算；两套日档目标相同的4个新情景复用，不是4份新证据。一个政策变体，零个新收益机制、公式参数或市场归档。2025/2026全部已查看，只作历史诊断。

没有虚构自动结算价、把TON无缝迁移至GRAM，或把终止后的零成交记录补为可交易价格。此前“纯满月源指数”仍保持未知；本次可交易的提前退出路径是另一明确合同，不能追溯改写旧指标。

## 恢复检查与失败记录

4条新政策账户、桥接和选定病例的现金／库存／资金费核验通过；新政策最大净值复算差1.35e-10USDT。持有／加仓后父PID29913与新PID29951恢复出的后续全部净值、现金、事件、请求、库存及最终风险状态逐项精确相同。错误的止损开关或旧引擎身份会被拒绝恢复。

原检查要求整张表逐bit一致，因敞口加总差最大4.55e-13USDT而中止。原错误和全部账户字节已封存，没有重跑收益。新独立核验从检查点和每笔成交重建166176行持仓，用实际前根价格及math.fsum复算总／净敞口；两条记录均在按持仓数推导的binary64求和误差界内，最大仅用到界的35.42%。这只解决敞口显示算术，净值和现金仍要求精确一致，并未放宽金额误差去掩盖经济差异。完整证据见restart_verification.json与exposure_summation_audit.json。

## 结题边界与下一步

“只要去掉8%单仓止损就能恢复可准入净收益”的解释未被支持。关闭当前固定实现的止损微调分支，容量未触发；不要以2026的正收益或一个TON病例替代608日连续结果。

不同环境可以用不同策略，因此不把整段失败外推为所有条件性趋势失效。下一步仅核对既有、在决策时可观察的行情状态与这些月度仓位／损失的适用域；先对齐状态原始数据、时点和成员，区分描述归因与可执行增量，不根据未来年份／收益筛选状态。若没有可支持的条件机制，就结束该分支再登记另一收益机制。

TradingAgents继续负责统一信号与研究，Freqtrade负责账户／政策验证，CZ-Agent沿用现有界面。总账户20%/30%年化、15%回撤、夏普1及多机制配置继续未完成。外部第三方复现、真正未见数据、客户现金及盘口容量均未建立，不下单、部署或推送。

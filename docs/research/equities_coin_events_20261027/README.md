# COIN原始业绩事件：发布时间冲突及固定账户归因

本轮继续深入已封存动量账户的主要正贡献者COIN，不扩大股票池、因子或经济账户。**50%扣费年化、回撤≤15%的目标没有达标；未取得新的策略准入、外部独立审计或真实前向账户记录。** 选择COIN作为核查对象发生在看过历史之后，以下内容是事后证据审查，不是事前选择赢家或独立样本外检验。

## 原件范围与事件分类

对固定窗口2023-01-03至2024-06-26内，CIK`0001679788`的所有Item 2.02申报逐份核对，共七份。CUSIP`19260Q107`、证券COIN与发行人身份另行绑定，没有将发行人CIK当证券永久身份。

七份完整SEC申报SGML均已保存。原始接受时间按纽约时区转换到UTC，与已封存API七项全部一致。二十份HTML可从父文件精确字节区间重建，其中**十三份为实质文档：七份主8-K、六份股东信；另外七份是辅助XBRL展示页，不能当七个额外事件或独立样本。** 本轮不声称这些非结构化股东信完成了Arelle财务数值验证。

Item 2.02并不自动意味着完整季度财报：2023-01-10的原件是初步未经审计业绩、未来指引及重组；其余六份才附完整季度/年度股东信。它们必须分开标注，也不能把原目录313份Item 2.02候选都当作313次已核实的首次财报公告。

## 官网结构化时间不能直接成为交易信号

另保存了六份发行人结果公告及六份提前公布业绩日期的通知。通知正文明确计划在市场收盘后发布，不能将问答会2:30 p.m. PT的开始时间当作财报发布时间。

六份官网结果页面的JSON-LD `datePublished`按字面UTC转换后都落在计划日的常规交易时段内。这首先是来源口径冲突，而不是可以自动修正的时区。**原字符串完整保留，均隔离，不用于历史盘中信号；没有自行加五小时或六小时。** 原封存股票实验仍使用SEC接受时间与既有一小时处理延迟，未接入这些官网字段，旧账户收益不重跑。

HTTP直连Business Wire原始页面的两次源采集未成功，失败记录保留。随后通过后台浏览器只读查看四份分发原站的可见日期字段，得到以下交叉核对。它们是原站显示的分钟级时间观察，不是假装下载成功的HTML，也不是独立审计人签署。

|---|---|---|---:|
| 2022Q4 | 2023-02-21T15:11:00Z | [21:11,21:12) | 6小时 |

分发页的美东夏令时/冬令时标签分别核对，精度保持一分钟，不伪造秒数。2023Q1的SEC接受时间20:05:52位于分发页显示分钟内，因此不能断言哪一个先了52秒；2023Q2分发页的声明时间先于SEC接受，而2022Q4和2024Q1则相反。**不能规定所有季度都统一先新闻稿、后SEC，或固定相差几分钟。**

这些来源都在2026年采集，当前网页的历史声明不是当年接收日志。分发源与公司IR可能复用同一新闻稿，并非两份独立财务真实性证明。完整财报也可能先在其他已定义渠道公开；四份原站时钟不证明全球首次公开。当前七个`absolute_first_public_at`均为空，尚无历史一致预期，不宣称复现PEAD或盈利惊喜策略。采用已验证SEC可得时间的保守研究可以继续，但不得改称第一条新闻反应研究。

# 持仓档案字段与时间标签核验

2026-10-16。在计算基差／OI扩展因子之前，先核对档案粒度、空值、跨日键和流量标签的经济时间；不计算收益或选择交易规则。
完整总体仍为v108事前固定的748合约×17日×两类依赖。采集中只能显式运行前缀诊断，每次先固定已落盘记录清单与SHA，后续记录不回填本次结果。
前缀按采集已完成项取得，具有合约字母顺序覆盖偏差，不能外推全市场覆盖或时钟一致性。完整审计须另建输出目录。

对每份metrics记录直接解析CSV，报告各列空值、零持仓、非递增顺序、五分钟参考网格缺点、同文件与跨日的相同／冲突键。
288点只是UTC日五分钟参考网格，不能据缺点推定没有市场活动，也不自动删除合约、补零、前向填充或排序后冒充原文有序。
已封存v093的分钟原文另含总基础成交量与主动买方基础成交量，可独立重建五分钟买量／卖量比。
固定比较两个候选解释：标记T代表[T−5分钟,T)或[T,T+5分钟)。使用原始分钟开盘时钟，五分钟必须全部存在、数量有效且卖量严格为正；任意缺失均记未知。
只在两个解释及档案字段均已知的共同样本比较误差、相关与近似相同数；不扫描额外偏移或按结果选择品种、日期。
核验容差事前固定为相对1e-6、绝对1e-8，只描述聚合与舍入的一致性；不以统计相关直接证明无未来数据。

公开仓库[问题491](https://github.com/binance/binance-public-data/issues/491)提供时间标签可能变化的可复验线索，属于提交者观察而非官方确认。
[官方数据字段](https://github.com/binance/binance-public-data)支持按分钟总基础量与主动买方基础量重建买卖量比；官方CHECKSUM仅证明字节一致。
即使某一流量解释吻合，也不能把该结论外推到存量OI、账户比或历史首次发布时间。OI仍须独立证据，扩展回归只能明确标为档案诊断。
冻结协议、全量或前缀身份、逐文件质量、全部配对量值和汇总一并保存；不读取带单员标签、私人账户或生产库存，不修改采集与原模拟进程。

后续完整审计同时接受来源合并视图：视图已封存不代表主采集已终态，必须读取原终态标记并核对原完整协议、每项原文及收据。未终态仍须显式前缀选项。
另核验全部已知指数档案的分钟结束时钟、有限正价格、高低开收约束、原顺序和同文件／跨日重复键；指数与metrics分别报告，缺失或冲突不补成中性值。
这些扩展只完善输入覆盖与字段审计，不改变先前两种流量窗口的定义，也不计算基差或OI盈利结果。
